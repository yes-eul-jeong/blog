# 인터프리터언어와 컴파일러언어

<br/>
<br/>

## 1\. 코드의 실행이란?

우리가 사용하는 소스코드는 비교적 사람에게 친숙한 언어다. 컴퓨터(CPU)는 0과 1로 된 기계어만 이해하는데 우리는 0과 1로만 명령어를 짤 수 없고, 이를 이해할 수도 없다. 이를 번역해주는 ‘번역기’ 역할이 바로 컴파일러와 인터프리터이다. 

<br/>
<br/>
<br/>
  

## 2\. 인터프리터 언어

_**한 줄씩 읽으며 바로 실행하는 언어**_ 

- 인터프리터는 코드를 한줄씩 해석하며 즉시 실행하는 방식이다. 
- 실행할때마다 소스코드를 다시 읽어야한다. 
<br/>
<br/>
  

### 특징

- 종류 : python, Javascript, Ruby...
- 코드 수정 → 바로 실행 가능(컴파일러 불필요)
- 테스트, 디버깅 편리
- 플랫폼 독립성이 높음(여러 OS에서 쉽게 실행 가능)

<br/>

### 단점

- 실행 시 매번 해석 → 실행속도 느림
- 런타임 에러가 실행 도중에 발견됨.

  
<br/>
<br/>

  

## 3\. 컴파일러 언어란?

_**한번에 미리 번역해서 실행파일을 만들어줘요.**_ 
<br/>
<br/>

  

- 컴파일러는 전체 소스코드를 한번에 기계어로 변환한 뒤, 실행파일을 만들어준다.
- 이후 컴파일된 파일만 실행하면 됨.
<br/>
<br/>

### 특징

- 종류 : C, C++, Go, Rust, Java (컴파일 후 JVM에서 실행)
- 실행속도 빠름( 컴파일 시 최적화 가능)
- 실해 전 대부분의 에러를 잡아냄(정적 분석에 강함)

<br/>

### 단점

- 수정 → 다시 컴파일 → 개발속도 느릴 수 있음
- 플랫폼에 따라 컴파일 옵션 다르게 설정해야함

<br/>
<br/>
<br/>
  

  

## 4\. 언어 적합성
<br/>

### 인터프리터 언어에 적합한 상황

- 빠른 프로토타이핑( 스타트업, 데이터 분석 등)
- 스크립트 자동화, 간단한 서버 (Node.js, Python)
- 배포 환경이 다양하거나 유연해야 할 때

<br/>
<br/>

### 컴파일 언어 적합 상황

- 고성능이 필요할 경우( 게임 엔진, 시스템 프로그래밍)
- 리소스 제약이 있는 환경(임베디드 시스템, 하드웨어 드라이버 등)
- 실행 안정성과 보안성이 중요한 경우

<br/>
<br/>
  

근데, 실무에선 상황과 목적에 따라 혼합사용하는 경우도 많음. (python으로 프로토타입 만들고 C++로 성능 개선)
