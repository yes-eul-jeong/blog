이 두 언어는 매번 언급하는데 매번 헷갈린다. 개념정리를 끝까지 제대로 안하고 애매하게 알고 넘어가니까 되돌아 봤을때 몇몇 키워드만 기억이 남고 머리에 안남는다.  
이참에 이 두 언어에 대해 완벽히 이해해보려한다.

 <br>
 <br>

## 1\. 프로그래밍 언어는 어떻게 실행될까

우리가 작성하는 언어는 컴퓨터가 바로 이해할 수 없다.
우리가 영화보면 나오는 해커들의 까만배경의 밝은 연두색의 0과 1로 가득한 화면. 그게 컴퓨터가 이해가능한 언어이다.

<br>

```javascript
let a = 10
let b = 20
console.log(a + b)
```

<br>

사실 컴퓨터는 이런 문자를 이해하지 못한다.

컴퓨터가 이해가능한 언어는 오로지 기계어(Machine Code)뿐이며 형태는 아래와 같다.

<br>

```
10110000 01100001
```

<br>

그래서 사람이 작성한 코드를 기계어로 번역하는 과정이 반드시 필요하다.

이 번역을 하는 방식이 두개가 있는데 그게 바로 인터프리터와 컴파일러다. 

<br>

<br>

---


## 2\. 인터프리터 언어

<br>

인터프리터는 코드를 실행하면 동시에 번역하는방식을 의미한다. 

대표적으로는

-  javascript
- Python

이 있다. 

<br>

인터프리터 방식은 아래와같이 프로그램이 실행된다.

```
코드 한 줄 읽음
↓
기계어로 번역
↓
바로 실행
↓
다음 줄
```

<br>

우리가 흔히 아는 자바스크립트 동작 방식이다.

즉, **코드를 미리 번역하지않고 실행하면서 번역**한다.

<br>

이 방식의 장단점은 무엇일까?

<br>

장점

- 실행이 빠름
- 수정 후 바로 실행 가능
- 개발 속도가 빠름

<br>

단점

- 실행 중 계속 번역 필요
- 성능이 비교적 느림

<br>

이러한 이유로 인터프리터언어는 보통

웹, 스크립트, 자동화 같은 분야에서 많이 사용된다.

그렇다면 컴파일러 언어는?

<br>
<br>

## 3\. 컴파일러 언어

<br>

컴파일러 방식은 인터프리터와 반대로 작동한다.

실행전 전체 코드를 한번에 번역한다.

<br>

대표적인 언어는

- C
- C++

등이있다.

<br>

컴파일 과정은 아래처럼 진행된다.

<br>

```
전체 코드 작성
↓
컴파일
↓
기계어 프로그램 생성
↓
실행

```

<br>

즉 실행 전에 완전한 프로그램 파일이 만들어진다.

<br>

그래서 실행할 때는 번역과정이 필요 없다. 

<br>

장점

- 실행속도가 아주 빠르다.
- 시스템 제어가 강력하다..

<br>

단점

- 수정할때마다 다시 컴파일과정이 필요하다
- 개발 과정이 조금 번거롭다.

<br>

이러한 방식은 보통 게임엔진, 운영체제, 고성능 프로그램같은 곳에서 사용된다. 

<br>

<br>

그렇다면 자바스크립트는 항상 느릴까? 내가 쉽게 접하는 것들중 어떤것이 인터프리터 언어로 개발되고 어떤것이 컴파일러 언어로 개발되었을까?

이러한 질문들에대해 알아보니 인터프리터와 컴파일러언어 두 가지를 함께 사용하는 경우가 많았다.

이것을 지칭하는 JIT컴파일라는 기술이 있다.

<br>

<br>

## 4\. JIT

JIT는 ‘Just In Time Compiler’의 약자로 아래와 같이 작동한다.

<br>

```
코드를 인터프리터로 실행
↓
자주 실행되는 코드 발견
↓
해당 코드를 기계어로 컴파일
↓
다음부터 매우 빠르게 실행

```

처음에는 인터프리터처럼 실행, 자주 실행되는 부분을 컴파일 하는 방식이다.

이 기술 덕에 인터프리터언어도 빠른 속도를 낼 수 있다.

이 기술을 활용하여 만들어진 프로그램엔 vscode나 figma가 있다. vscode는 electron을 이용하여 만들어진 프로그램이므로 웹앱을 그대로 프로그램 실행, 웹으로 띄우기가 가능하다.
